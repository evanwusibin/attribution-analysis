# 外部能力集成与运行架构规格

> **状态**：draft。本文定义售前售后统一归因的模块边界与外部能力接入方式；不将 Docker 骨架或未验证服务表述为可运行交付。

## 1. 模块与数据流

```text
工作台
  → API：认证、命令、查询、事件恢复
    → Case 应用服务：生命周期、幂等、版本与授权
      → 编排器：计划、取消、超时、降级
        → 工具注册表：场景白名单
          → CRM / 售后快照适配器
          → NL2SQL HTTP 适配器
          → RAG HTTP 适配器
          → 确定性规则适配器
        → Evidence 服务 → Result / Review / Export
```

售前 E1–E5 与售后 S1–S5 只在场景路由、可用工具、语义视图、规则和黄金断言上不同；不得各自实现新的编排器、状态机或证据结构。

## 2. 外部能力契约

| 能力 | 接入方式 | 允许输入 | 必须输出 | 失败降级 |
|---|---|---|---|---|
| CRM 售前快照 | 只读适配器 | 场景意图、允许字段、时间窗、行数限制 | 标准化快照、读取时刻、来源定位、来源等级 | 返回 `MISSING` 与补数来源，不执行任意 SQL |
| 售后业务快照 | MySQL/fixture 只读适配器 | VIN、工单、索赔、网点、供应商等白名单标识 | 标准化快照、种子/规则版本 | 记录缺失，禁止把模拟数据升级为事实 |
| NL2SQL | HTTP 服务适配器 | 受控意图及语义视图，不直接接收自由 SQL | 摘要、字段来源、查询版本、行数/超时结果 | 拒绝无来源或不合规响应；独立失败不阻断其他工具 |
| RAG | HTTP 服务适配器 | 查询、知识库版本、权限范围 | 片段、文件/章节定位、相关度、语料版本 | 无命中为 `MISSING`；不可生成假引用 |
| MCP | 外部 DashScope MCP 或未来独立工具服务 | 由 RAG/适配器受控调用 | 标准化检索结果和来源 | 不存在本地 MCP Server 时明确禁用，不能以空容器替代 |

## 3. Docker 分层

| 层级 | 服务 | 启动标准 |
|---|---|---|
| `core`（默认） | `frontend`、`attribution-api` | 完成配置展开、镜像构建与 API/前端健康检查后才可标记可运行。API 当前使用内存公共内核，不依赖数据库容器。 |
| `integrations` | `postgres`、`mysql`、`mongo`、`minio`、`etcd`、`milvus`、`qdrant`、`elasticsearch`、`embedding`、`rag-import`、`rag-query`、`nl2sql` | 显式使用 `--profile integrations` 启用；仅在源码路径、模型挂载、数据库密码及外部服务密钥的前置条件满足后验证。 |
| `learning` | pgvector 等实验能力 | 可随 `postgres` 一并启动，但不承担与 Milvus/Qdrant 重复的正式检索职责。 |

Compose 插值必须显式使用 `--env-file .env.example`（或由本机 `.env` 提供同等非敏感配置）；服务进程则按 `.env.example` 后可选 `.env` 的顺序读取变量，后者覆盖模板。`docker compose --env-file .env.example config --quiet` 已通过展开验证；这只证明配置完整，不代表任一容器已启动。

## 4. 运行验收顺序

1. 验证配置展开，不读取或提交真实密钥。
2. 仅启动 `core`，检查数据库、API、前端健康状态和种子结果。
3. 单独启动 `rag`，验证导入前置、查询健康与无命中降级。
4. 单独启动 `nl2sql`，验证元数据构建、只读约束、超时和来源返回。
5. 联调归因 API 的 HTTP 适配器；以真实日志、健康检查和端到端黄金案例记录运行证据。
