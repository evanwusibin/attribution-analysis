# 概要设计与领域行为蓝图

> **状态**：draft / D2–D3。
>
> **上游来源**：`02_经营归因开发任务/03_技术方案与架构.md`、`specs/G1_领域模型、状态机与验收契约.md`。
>
> **边界**：本文定义职责、数据流和失败行为；不授权任何业务实现、外部连接或依赖安装。

## 1. 系统边界

```text
归因工作台
  → 归因 API（输入校验、幂等、读取、取消、导出）
    → Case 应用服务（任务与会话）
      → 归因编排器
        ├→ 计划器
        ├→ 只读工具注册表
        │   ├→ 业务数据适配器
        │   ├→ 手册/政策适配器
        │   └→ 确定性规则适配器
        ├→ 证据服务
        └→ 结果合成器
    → 运行数据存储 / 规则版本 / 黄金数据
```

外部 CRM、DMS、RAG 与 NL2SQL 均在“适配器”边界之外。系统只接收其只读、带来源定位的响应；不得直接导入 `CRMProject_c` 内部模块或向任何外部系统写入。

## 2. 模块职责矩阵

| 模块 | 输入 | 输出 | 唯一职责 | 明确禁止 |
|---|---|---|---|---|
| 归因工作台 | 用户输入、任务快照、证据、结果 | 用户操作与状态展示 | 呈现七态和来源等级 | 推导业务结论、隐藏失败、发起外部处置 |
| 归因 API | 外部请求、幂等键、身份上下文 | 用例命令/查询、标准错误 | 校验边界、幂等路由、读写用例编排 | 直接访问业务工具或拼接结论 |
| Case 应用服务 | 创建/追问/取消命令 | `AttributionCase` 状态变更 | Case 与 Conversation 的生命周期 | 修改外部索赔/DMS 状态 |
| 归因编排器 | Case、当前 Plan、取消标记 | 下一状态、计划/执行/证据/结果命令 | 执行状态机与步数上限 | 内嵌车型、索赔、SLA 等领域规则 |
| 计划器 | 结构化问题、当前证据、场景约束 | 可验证的 `AnalysisPlan` | 产生受白名单约束的子问题与工具序列 | 将计划当结论、直接调用外部系统 |
| 工具注册表 | 工具名、受控输入、执行上下文 | `ToolExecution` 结果 | 选择唯一只读适配器与规范化错误 | 调度未知工具、绕过超时/审计 |
| 证据服务 | 工具原始响应、规则快照 | 不可变 `Evidence` | 记录来源三元组、摘要、原始定位 | 用默认值补齐来源或覆盖历史证据 |
| 结果合成器 | 已验证 Evidence、缺失项、结果版本 | `AttributionResult` | 六段结果与不确定性表达 | 无证据断言、自动审批/追偿/扣款 |
| 规则版本服务 | 规则/阈值快照 | 版本化、来源分级规则 | 将 FACT、MOCK、MISSING 显式隔离 | 把模拟阈值升级为真实制度 |
| 适配器 | 受控查询 | 标准化外部只读响应 | 隔离 CRM/DMS/RAG/NL2SQL 技术差异 | 泄露写能力或内部依赖 |

## 3. 核心数据流

### 3.1 正常归因

```text
有效输入 + 幂等键
  → 创建或复用 AttributionCase
  → validating
  → planning：保存 AnalysisPlan(vN)
  → executing：为当前步骤创建 ToolExecution
  → 工具只读响应
  → 追加 Evidence（source_class/source_ref/rule_version）
  → planning（仍需证据）或 synthesizing（证据充分）
  → 写入 AttributionResult(vN)
  → completed
```

**根不变量**：结果只引用同一 `case_id` 下已经持久化的证据；证据只能追加，结果只能新建版本，不能覆盖历史版本。

### 3.2 证据不足

```text
执行步骤
  → 关键字段/规则为 MISSING
     或关键判断只受 MOCK 支撑
  → 记录已获得证据与缺失项
  → needs_input
  → 工作台 P-05：显示补数来源与人工复核
```

该链路**不产生责任裁决**。追问必须创建新的 `AnalysisPlan` 与 `AttributionResult` 版本，并可复用已验证证据。

### 3.3 工具失败与取消

```text
瞬时工具失败 → 仅重试一次 → 仍失败则记录 ToolExecution=failed/timeout
                                     → 独立步骤继续；聚合为部分成功或待补充
用户取消 → cancel_requested_at
          → 当前只读操作完成边界检查
          → cancelling → cancelled
          → 保留已写 Evidence；禁止调度下一步骤
```

## 4. 领域对象关系

```text
Conversation 1 ── N AttributionCase
AttributionCase 1 ── N AnalysisPlan
AttributionCase 1 ── N ToolExecution
AnalysisPlan    1 ── N ToolExecution
ToolExecution   1 ── N Evidence
AttributionCase 1 ── N AttributionResult
```

| 对象 | 拥有者 | 版本规则 | 关键约束 |
|---|---|---|---|
| `Conversation` | Case 应用服务 | 摘要版本递增 | 组织追问，不代替 Case |
| `AttributionCase` | Case 应用服务 | 生命周期内单一主状态 | 不修改外部业务单据 |
| `AnalysisPlan` | 归因编排器 | 每次规划/追问产生新版本 | 最大 8 步，工具必须在白名单 |
| `ToolExecution` | 工具注册表 | 不可覆盖 | 唯一键阻止重复调度 |
| `Evidence` | 证据服务 | 只追加 | 必有来源三元组与原始定位 |
| `AttributionResult` | 结果合成器 | 只新增修订版本 | 所有结论可追溯到 Evidence |
| `ClaimSnapshot` | 适配器 | 读取时刻快照 | 外部只读，不进入归因状态机 |

## 5. 状态与失败归属

| 失败或边界 | 归属模块 | 状态结果 | 用户可见含义 |
|---|---|---|---|
| 输入少于 5 字 | API / Case 应用服务 | `rejected` | 要求补充具体异常，不创建计划 |
| 相同请求重复提交 | API / Case 应用服务 | 复用原 Case | 返回既有进度，不重复查数据 |
| 计划不合法或超过 8 步 | 编排器 | `failed` 或 `needs_input` | 显示已有证据与未完成问题 |
| 单工具 10 秒超时 | 工具注册表 | `ToolExecution=timeout` | 部分成功，其他独立证据继续展示 |
| 整案 30 秒超时 | 编排器 | `needs_input` 或 `failed` | 保留证据，说明无法安全合成 |
| `MISSING` / 关键 `MOCK` | 证据服务 + 合成器 | `needs_input` | 人工复核与补数清单 |
| 用户取消 | Case 应用服务 + 编排器 | `cancelled` | 保留已得证据，不再执行后续步骤 |
| 外部响应不含来源 | 适配器 + 证据服务 | `failed` 或 `needs_input` | 不渲染为可信证据 |

## 6. 外部能力适配契约

| 能力 | 适配器输入 | 最小输出 | 安全约束 |
|---|---|---|---|
| 业务数据查询 | 受控查询意图、允许对象、行数/时限 | 数据摘要、字段来源、查询版本 | 只读、白名单、超时、行数限制 |
| 手册/政策检索 | 查询、语料版本 | 片段、文件/章节定位、置信度 | 无命中即 `MISSING`，不生成假引用 |
| 确定性规则 | 业务快照、规则版本 | 命中条件、解释、来源等级 | `MOCK` 不能驱动处置；规则输入完整性可验证 |
| CRM/DMS 快照 | 外部标识与只读授权 | 读取时间、来源、标准化字段 | 不暴露写操作，不将外部状态映射为 Case 状态 |

## 8. 知识摄取、双路归因与工作台能力目录

### 8.1 导入职责

附件导入**不写入 NL2SQL 业务库**。NL2SQL 始终是受控只读的业务数据查询通道；导入链路为：

```text
用户选择附件 → Case 所有权校验 → 隔离原文件 + SHA-256
  → 解析快照 → 知识条目元数据（MySQL）→ 向量化任务（向量库）
  → RAG 召回 → Evidence(source_ref=attachment:*)
```

MySQL 保存附件、解析快照、向量任务与审计索引；向量数据库仅保存可检索分块及其 embedding。两者以 `attachment_id`、内容哈希和知识版本关联。任一路不可用时，必须记录失败 Evidence/Execution，另一路继续执行；不得将部分成功伪装为整案失败或成功。

### 8.2 工作台可用范围

- 工作台、案件、会话历史、证据中心、分析轨迹、新建会话：读取同一主体的 Case、Plan、Execution、Evidence、Result。
- 知识库：展示 MySQL 中的知识元数据、解析状态和版本；检索结果由向量库返回，并以来源定位回链元数据。未配置向量库时显示“索引待接入”，不伪造检索结果。
- 导出中心：仅从 Case 已持久化的 Result/Evidence 生成 HTML-first 报告；预览、下载和审计均绑定 Case 与主体。
- 提交问题后，欢迎页转换为归因整体链路：问题 → Plan → NL2SQL/RAG → Evidence → Result → 人工复核。

### 8.3 场景目录

售前目录为 E1–E5；售后与服务目录为 S1–S8。专项投影已注册的场景走其领域服务；尚无专项投影的已批准场景走通用双路归因，并在结果中公开“专项规则待接入”的限制。
