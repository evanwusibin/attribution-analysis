# 归因工作台原型蓝图与 Pencil 评审包

> **状态**：draft / D6。本文将 G1 原型状态契约转为可绘制、可评审的交付清单；不定义后端实现，不替代领域状态机。
>
> **上游来源**：`G1_原型评审与界面状态契约.md`、`ATTRIBUTION_API_V1.md`、`ARCHITECTURE_AND_BEHAVIOR_BLUEPRINT.md`。

## 1.0 对话优先与结果按需展开

默认交互不是先展示分析仪表盘，而是先完成一轮可理解的业务对话：

```text
用户描述经营问题
  → 助手澄清对象 / 时间 / 维度 / 场景
    → 用户确认分析范围
      → 对话中展示 Plan / RAG / 受控 NL2SQL / 流式进度
        → 右侧按需展开 Evidence / 评估 / Result
          → 追问继续留在同一会话，并创建新版本
```

左侧只承载会话与场景导航；中间是消息流和输入台；右侧是可折叠结果抽屉。默认示例必须使用通用经营归因场景。电池包故障仅作为 S1 故障诊断下的配置域，不得出现在默认问题、默认会话标题或默认结果中。


```text
┌ 会话侧栏 ───────┬ 问题与输入 ───────────────────────────────┐
│ 会话标题         │ 场景提示、当前问题、提交 / 取消            │
│ 当前任务状态     ├ 分析计划 ─────────────────────────────────┤
│ 最近更新时间     │ 步骤、进度、当前查询目标                   │
│                  ├ 证据清单 ─────────────────────────────────┤
│                  │ FACT / MOCK / MISSING、来源、规则版本      │
│                  ├ 结果 / 待补充 ────────────────────────────┤
│                  │ 六段结果、人工复核、追问、导出             │
└──────────────────┴─────────────────────────────────────────┘
```

| 区域 | 必须固定呈现 | 不得呈现 |
|---|---|---|
| 会话侧栏 | 会话标题、当前 Case 状态、最近更新时间 | 技术 ID、堆栈、其他主体 Case |
| 输入区 | 问题、场景提示、字符校验、提交/取消 | DMS 写回、审批或处罚操作 |
| 计划区 | 已计划步骤、当前步骤、最大 8 步 | 未执行步骤的结果 |
| 证据区 | 摘要、文字来源标签、定位、规则版本、置信度 | 来源不明的可信结论 |
| 结果区 | 六段结果、缺失项、人工复核、追问、导出 | 自动拒赔、扣款、追偿、降级按钮 |

## 1.1 企业级可审计分析轨迹

原型展示可复核的**分析轨迹**，而非模型原始思维链。轨迹中的每项均对应已持久化的 Plan、ToolExecution、Evidence 或 Result 版本，因此用户可以核验系统做过什么、基于什么得出建议，而不会把内部提示词或不稳定推理草稿伪装为事实。

```text
输入与任务边界
  → Plan vN：子问题与最多 8 个只读步骤
    → RAG：检索查询、语料版本、重排命中、来源定位
      → NL2SQL：自然语言意图、候选查询摘要、白名单校验、参数、行数/超时边界
        → Evidence：FACT / MOCK / MISSING、快照、规则版本、置信度
          → 评估：相关度、完整度、一致性、冲突与缺失
            → Result vN：流式建议、证据引用、人工复核限制
```

| 轨迹区域 | 用户可见内容 | 约束 |
|---|---|---|
| 企业壳层 | 当前 Case、环境、只读治理标签、审计入口、版本 | 不展示数据库凭据、技术堆栈或其他主体 Case |
| 步骤流 | 排队/执行/完成/超时/取消中状态、耗时、持久化事件 | 只能显示已发生事件；未执行步骤不得伪造输出 |
| RAG 检索 | 查询摘要、知识库版本、重排后命中、来源定位与相关度 | RAG 命中不是制度结论；无命中必须标记 `MISSING` |
| NL2SQL 受控查询 | 业务意图、候选查询摘要、参数范围、白名单/只读角色、行数与超时结果 | 不展示可执行任意 SQL，不允许 Agent 直连数据库或持有凭据 |
| 证据评估 | 相关度、完整度、一致性、冲突与缺失，以及 Evidence 版本 | RAG 语义评估与 NL2SQL 固定值校验分开显示；不可把分数替代来源 |
| 流式结果 | 已生成的建议片段、引用 Evidence、结果版本、完成/降级原因 | 片段必须明确是草稿或已持久化版本；关键 `MISSING`/仅 `MOCK` 时强制人工复核 |

企业视觉基线：浅色工作区、深色治理顶栏、统一状态徽标与分组卡片、8px 间距体系、清晰的层级标题和高对比文字。`FACT`、`MOCK`、`MISSING` 同时使用文字、图标形状与辅助文本，不依赖颜色。

## 2. 七张 Pencil 画板

| 画板 | 绑定状态 | 必须内容 | 可用操作 | 禁止操作 |
|---|---|---|---|---|
| P-01 空态 | 无 Case / 输入拒绝 | 示例问题、S1–S5 范围提示、数据来源说明、输入错误文字 | 创建分析 | 虚构历史结论或进度 |
| P-02 计划 | `planning` | 问题摘要、计划骨架、加载占位、取消入口 | 读取进度、取消 | 将计划写成结论 |
| P-03 执行 | `executing` | 已完成/当前/待执行步骤、已得 Evidence | 查看证据、取消 | 展示未来步骤结果 |
| P-04 部分成功 | `executing` 或 `synthesizing` 且有非致命失败 | 成功证据、失败工具、缺失数据、降级说明 | 继续等待、取消、读取证据 | 显示整体成功 |
| P-05 待补充 | `needs_input` | 缺失字段、预期提供方、人工复核原因、历史证据 | 追问、导出 | 责任裁决或处置动作 |
| P-06 已取消 | `cancelled` | 取消时间、已完成步骤、保留 Evidence、未执行计划 | 追问、导出 | 恢复原计划或调度后续工具 |
| P-07 已完成 | `completed` | 六段结果、证据引用、来源标签、结论限制 | 追问、导出、查看证据 | 隐藏 `MOCK`/`MISSING` 或处置按钮 |

## 3. 画板跳转与 API 对照

```text
P-01 --有效创建--> P-02 --> P-03 --> P-07
                         │       ├--> P-04
                         │       ├--> P-05
                         │       └--> P-06
P-05 / P-06 / P-07 --追问--> P-02
```

| 触发 | API 契约 | 前端反馈 | 不变量 |
|---|---|---|---|
| 输入少于 5 字 | 本地校验 / `CASE_INPUT_INVALID` | 留在 P-01，显示具体补充提示 | 不创建 Case |
| 有效提交 | `POST /cases` | 5 秒内 P-02 或明确拒绝 | 幂等键不能重复执行 |
| 进度轮询 | `GET /cases/{case_id}` | P-02/P-03/P-04 状态同步 | 只显示已持久化进度 |
| 单工具超时 | Case 含 `TOOL_PARTIAL_FAILURE` | 进入 P-04 | 其他已得 Evidence 保留 |
| 关键缺失/仅 MOCK | Result 标记人工复核 | 进入 P-05 | 不展示自动裁决 |
| 取消 | `POST /cancel` | 先显示“取消中”，确认后 P-06 | 已写 Evidence 不消失 |
| 追问 | `POST /follow-ups` | 新 Plan 版本回到 P-02 | 旧证据与 Result 版本可回看 |
| 导出 | `POST /exports` | 显示生成状态 | 导出仍保留来源和限制 |

## 4. 来源等级与风险表达

| 标签 | 必须文字 | 结果区约束 |
|---|---|---|
| `FACT` | “可定位来源” + 文件/记录章节或读取定位 | 可作为事实依据；责任仍无自动处置 |
| `MOCK` | “模拟数据/规则” + 版本 + “不可自动处置” | 只能构成演示候选结论 |
| `MISSING` | “待补充” + 所缺字段 + 预期来源 | 强制展示人工复核与补数路径 |

来源等级不能只依赖颜色；文字标签、图标形状和辅助文本必须同时存在。P-04 至 P-07 均需显示已引用证据的来源等级，不能只在证据详情中暴露。

## 5. Pencil 绘制清单

- 创建一个画布，包含 P-01 至 P-07 七个画板及第 3 节跳转线。
- 使用第 1 节固定骨架，画板仅体现状态允许的差异。
- 使用企业壳层与“可审计分析轨迹”展示 Plan、RAG、NL2SQL、Evidence、评估与 Result 版本；不得展示模型原始思维链。
- RAG 区展示语料版本、重排命中、来源定位和相关度；无命中必须进入 `MISSING` / 补数路径。
- NL2SQL 区只展示受控查询意图、摘要、参数和白名单校验结果；不展示任意可执行 SQL、连接串或凭据。
- 流式区按已持久化事件展示工具状态、耗时、输出片段与降级原因；严禁伪造未来步骤或未发生输出。
- 为每个 Evidence 卡片保留：摘要、`FACT/MOCK/MISSING` 文本、来源定位、规则版本和展开入口。
- 在 P-05、P-06、P-07 上展示“追问创建新分析版本，保留既有证据”的说明。
- 在 P-05、P-07 明确显示“建议/人工复核”，不使用“已审批/已拒赔/已追偿”等处置用语。
- 导出原型时命名为 `attribution-workbench-g1-draft`，不得标注为“已验收”。

## 7. 深度优化稿视觉与交互契约

本轮优化不改变 G1 状态机，只改变信息分组和可见反馈。目标是把“结果抽屉”从信息堆叠改为可读的分析工作台。

### 7.1 企业壳层

```text
┌ 左侧导航 ──┬ 会话与对话主线 ───────────────────────┬ 结果抽屉 ─────┐
│ 工作台      │ 顶部：Case / 场景 / 只读治理状态       │ 结果摘要      │
│ 会话        │ 用户问题与助手澄清                     │ 关键指标图表  │
│ 证据        │ 当前回合消息                           │ 归因结论      │
│ 分析轨迹    │ 分析流程图（可展开节点）               │ 证据与限制    │
│ 导出        │ 底部：附件、输入、取消/提交             │ 导出/追问      │
└────────────┴───────────────────────────────────────┴──────────────┘
```

- 左侧导航固定宽度，承载工作台、会话、证据、分析轨迹和导出入口；不把技术 ID 当作导航文案。
- 顶部保留当前 Case、场景、数据环境、只读治理徽标和更新时间。
- 中间保持对话优先；流程图是当前回合的可审计进度卡，不替代对话。
- 右侧结果抽屉默认展开摘要，证据、限制和版本详情按需展开。

### 7.2 专业图表契约

| 图表 | 表达内容 | 必须标注 | 禁止误导 |
|---|---|---|---|
| 指标趋势图 | 时间区间内的核心指标变化 | 指标名、单位、周期、来源等级、规则版本 | 不用无来源曲线暗示因果 |
| 归因贡献条形图 | 候选因素与影响量/占比 | 候选性质、计算口径、证据数量、置信度 | 不把候选贡献显示成责任裁决 |
| 证据覆盖矩阵 | 子问题 × 证据类别的覆盖情况 | `FACT/MOCK/MISSING` 文字标签、来源版本 | 不用“100% 覆盖”替代证据质量 |
| 结果摘要卡 | 关键指标、缺失项、人工复核 | 数值、单位、时间、来源和限制 | 不隐藏 `MOCK/MISSING` |

图表颜色只能作为辅助编码；来源等级同时显示文字、形状和辅助说明。图表无数据时显示“暂无可用证据”，不绘制 0 值占位。

### 7.3 流程图式分析轨迹

```text
[输入边界] → [Plan] → [RAG 检索] → [受控 NL2SQL] → [Evidence] → [评估] → [Result]
                  └──────── 当前节点高亮；已完成节点渐隐；未执行节点弱化 ────────┘
```

每个节点内部固定三层内容：

```text
节点标题 / 状态徽标
  ├─ 执行步骤：校验 → 调用白名单工具 → 标准化 → 写入审计事件
  ├─ 当前工作：正在处理的业务动作与参数摘要（不显示凭据/任意 SQL）
  └─ 产出：已持久化事件、Evidence 数量、缺失/失败摘要
```

- `queued`：低对比度虚线边框，不显示未来产出。
- `running`：节点边框渐变高亮，内部当前步骤带短暂光带；只显示已发生事件。
- `succeeded`：保留来源徽标与耗时，整体降低对比度，避免与当前节点争夺视觉焦点。
- `failed/partial`：使用警示图形和文字，保留成功 Evidence，明确缺失原因。
- `needs_input`：节点停在补数入口，显示缺失字段、预期来源和人工复核原因。
- `cancelled`：停止后节点冻结，显示已完成步骤和“未执行”步骤，不伪造失败。

动态效果只表达当前持久化状态，不表达模型内部推理。动画不可作为唯一状态反馈；静态状态徽标和文字必须独立可读。

### 7.3.1 P-03 执行态的固定流程图结构

P-03 不使用“并列信息卡”模拟流程，而是固定呈现从左到右、单向连接的五个可审计节点。原型当前展示第三个节点为运行中，运行时可根据最新持久化事件移动当前节点，并只展开一个节点。

```text
[输入边界 ✓]  ···→  [RAG 检索 ✓]  ···→  [受控查询 运行中]  ···→  [证据评估 待执行]  ···→  [流式结果 待执行]
                                             │
                                             └─ 当前节点展开：任务 / 状态 / 子任务 / 输入 / 输出 / 审计信息
                                                                    ↘ 右侧：当前节点明细
```

| 节点 | 卡片内稳定内容 | 当前节点展开内容 | 产出边界 |
|---|---|---|---|
| 输入边界 | 场景、时间窗、权限与 `correlation_id` 状态 | 解析会话/Case → 校验场景与时间窗 → 生成关联标识 | 仅显示通过或拒绝的输入边界事件 |
| RAG 检索 | 语料版本、命中数量、来源等级 | 白名单检索 → 版本筛选 → 来源标准化 → 审计落点 | 只显示已命中的来源，不把命中等同于结论 |
| 受控查询 | 语义视图、参数范围、行数/超时 | 意图映射模板 → 参数绑定 → 只读语义视图 → 结果上限控制 | 不展示任意 SQL、凭据或未执行查询结果 |
| 证据评估 | Evidence 等级、规则版本、冲突/缺失 | 分级 → 冲突/缺失检测 → 规则版本绑定 → 人工复核判断 | `MISSING` 或仅 `MOCK` 必须停在复核出口 |
| 流式结果 | 版本、引用数、草稿/已持久化状态 | 结构化事件 → 结论草案 → 引用绑定 → 审计落点 | 仅呈现已持久化片段，不伪造最终结论 |

静态原型以短分段虚线与箭头表现流向；运行时使用沿连接线移动的低频高亮点、当前节点青色光晕和已完成节点渐隐，表示“执行到哪里”。待执行节点保持低对比度且不展示输出。右侧明细随当前/用户选中的节点同步切换，但不得展示模型原始 CoT。

### 7.4 深度视觉基线

- 采用浅色工作区 + 深色左侧治理导航；主色使用冷蓝，运行高亮使用青色，风险/缺失使用琥珀与红色。
- 使用 8px 间距体系、12px 圆角、1px 分隔线和明确的卡片层级；正文优先保证对比度。
- 图表与流程节点使用同一套来源徽标、时间、版本和审计信息组件。
- 结果抽屉按“摘要 → 图表 → 证据 → 限制 → 动作”排序，减少纵向回溯。
