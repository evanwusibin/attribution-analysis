> 本文只记录静态原型的结构与交互检查，不代表后端业务实现、接口验收或项目整体验收。

## 1. 结构验证
- **左侧导航**：宽度 220px，包含笔划风格图标，展示「当前对话」活跃状态。  
- **中心底部输入区**：拥有单行输入框、文字提示「继续追问或补充案件信息…」以及「发送」按钮，符合 P-01 输入区约束。  
- **右侧审计结果面板**：固定在页面右侧，标题「当前任务详情」，列出步骤、当前步骤、允许/禁止能力等信息，满足审计面板要求。

## 2. 交互流验证
- **五节点流程图**：`optP01 → optP02 → optP03 → optP04 → optP05` 以水平卡片形式呈现，卡片间使用虚线矢连接。  
- **状态可视化**：  
  - **Done**：绿色边框 + ✓ 勾子图标。  
  - **Running**：琥珀色边框 + 循环 spinner。  
  - **Waiting**：红色边框 + ⏳ 时钟图标。  
- **节点展开**：点击卡片可展开，显示任务描述、输入负载、输出结果、子任务列表；右侧审计面板同步更新对应的审计细节。

## 3. 合同边界检查
- **未引入后端业务能力**：本轮只检查原型结构和静态内容，没有新增业务代码、数据库访问、API 调用或真实数据连接。
- **原型数据性质**：节点内容是静态演示载荷，仅用于检查状态展示、来源标签和审计信息布局，不能作为运行时证据。
- **权限边界**：原型不提供 DMS 写入、审批、扣款、降级或追偿操作。
