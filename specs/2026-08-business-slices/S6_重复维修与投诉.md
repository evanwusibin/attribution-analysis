# S6 · 重复维修与客户投诉归因切片 Spec

> **状态**：implemented（2026-08-17 本地实现）
> **依赖**：S3 售后共享证据底座

## 1. 范围

### 目标
- 识别重复维修（同一 VIN + 同一故障码 ≥2 次）的归因
- 关联投诉记录、技师画像、SLA 事件
- 输出维修质量 / 技师技能 / 服务时效的候选归因

### 非目标
- 不自动处罚技师或服务店
- 不自动赔偿客户

## 2. 数据与规则

| 数据对象 | 来源等级 | 规则 |
|---|---|---|
| complaints | MOCK | 投诉类型/严重度/状态 |
| repair_attempts | MOCK | 同 VIN+故障码 ≥2 次 → 重复维修 |
| technician_profiles | MOCK | 成功率 <80% 阈值 → 技能不足候选 |
| service_sla_events | MOCK | is_overdue=1 → 时效违规 |

- 所有阈值标记 `MOCK`（无原始制度依据）
- 缺失数据标记 `MISSING`

## 3. 接口

`POST /api/v1/complaint-analysis/diagnostics`
```json
{"question": "投诉修了3次没修好", "vin": "LSGAB52R7DF000001"}
```

## 4. 测试契约

- 重复维修检测（同 VIN 同故障码 ≥2 次）
- MISSING 降级（无投诉记录时不伪造）
- 人工复核门禁（MIT 归因不自动归责）

## 5. 验收

- 输出六段结构（问题/指标/结论/缺失/复核/证据）
- 86/86 测试通过中包含 S6 场景
