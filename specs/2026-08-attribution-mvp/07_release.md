# 07 Release Plan

> 只记录已执行的发布动作与实际结果；未执行的发布计划标记为待办。

## 1. 当前发布边界（本地演示 MVP）

- **已发布范围**：本地单进程 FastAPI 演示服务 + 同源工作台（`/workbench/`）。
- **证据边界**：当前所有演示证据为 `MOCK`（`demo.duckdb.business.v1`、`demo.manual.v1`），结果强制 `manual_review_required=true`。
- **禁止声明**：不得把本地演示数据、`X-Subject-Id` 测试主体或内存状态描述为生产能力（见 `00_可执行交付基线.md` §1）。

## 2. 发布步骤（本地演示 MVP）

1. 安装：`uv sync --extra dev`
2. 初始化演示库：`uv run python scripts/init_demo_db.py`
3. 启动：`uv run uvicorn attribution_analysis.app:app --reload`
4. 健康检查：`GET /health` 返回 `{'status': 'ok', 'service': 'attribution-analysis'}`
5. 冒烟验证：`uv run pytest`（99 passed，见 06_acceptance.md）

## 3. 监控指标

| 指标 | 当前状态 |
|---|---|
| 测试通过率 | 99/99（本地） |
| 健康检查 | `GET /health` 200 |
| 服务端口 | 8001（uvicorn，开发无 `--reload` 时需手动重启） |
| 依赖健康 | MySQL/CRM/DMS/向量库均未接入，演示不依赖外部服务 |

## 4. 集成/生产发布（未开始，准入条件）

以下能力进入实现/发布前必须具备（引用 `00_可执行交付基线.md` §4）：

- 真实 CRM/DMS：数据所有人授权、只读语义视图、行级范围、脱敏清单、可复现快照和集成测试。
- 真实 RAG：文档版权/版本清单、切分策略、引用定位、访问范围和检索评测集。
- 持久化审计：PostgreSQL 模式迁移、保留期、备份恢复演练和并发策略。
- OAuth/网关认证：IdP 对接、会话生命周期、角色矩阵和威胁建模。
- 模型部署：LLM/Embedding 服务健康检查、显存与并发配置、应用与模型联调（见 `通用技能库\03_部署上线_通用Skill.md`）。

## 5. 回滚方案

- **当前演示版本**：无外部写入、无数据迁移，回滚 = 回退 git 提交（仓库 `attribution-analysis-agent`）后重启服务。
- **集成/生产版本（实施前必须补齐）**：
  1. 回滚触发条件：错误率超阈值、核心链路不可用、数据异常（量化阈值在发布前定义）。
  2. 镜像/版本回退：`docker compose` 指向上一版本镜像 tag。
  3. 数据回退：如含数据库迁移，准备回退脚本。
  4. 回滚后冒烟验证：健康检查 + 核心链路逐条验证。
- 应急联系人：项目负责人（邬思彬）。

## 6. 发布检查清单（每次发布前逐项勾选）

- [ ] 测试与业务验收证据齐备（06_acceptance.md 有记录，缺证据标红不推测）
- [ ] 无密钥硬编码、`.env` 不入库、无真实业务数据入库
- [ ] 版本范围与配置变更明确
- [ ] 监控指标可观察
- [ ] 回滚方案已准备
- [ ] 演示数据不声明为生产能力
